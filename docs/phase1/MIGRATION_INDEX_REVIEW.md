# Phase 1 — Live Schema and Index Review

## Scope

This review evaluates the read-only Prisma schema diff reported by the user's Windows PostgreSQL database after migration deployment. No SQL generated by `prisma migrate diff` was executed.

## Evidence

The command used the Prisma 7 configuration-aware syntax:

```powershell
& $pnpmCmd --filter api exec prisma migrate diff `
    --from-config-datasource `
    --to-schema 'prisma/schema.prisma' `
    --config 'prisma.config.ts' `
    --script
```

The live database reported one extra index relative to the current Prisma schema:

```sql
DROP INDEX "OutboxMessage_status_createdAt_idx";
```

The database query verified that ten indexes currently exist. The extra index is `OutboxMessage_status_createdAt_idx`; the current schema declares `OutboxMessage_status_availableAt_createdAt_idx`, `OutboxMessage_status_claimedAt_idx`, and `OutboxMessage_aggregateType_aggregateId_idx` instead.

## Dependency-chain review

| Layer | Evidence | Finding |
|---|---|---|
| Prisma model | `backend/api/prisma/schema.prisma:20-39` | The current model has `attempts`, `availableAt`, `claimedAt`, `leaseToken`, and `deadLetteredAt`, with indexes matching current delivery semantics. |
| Published migration | `backend/api/prisma/migrations/20260820190000_outbox_delivery_semantics/migration.sql:9-14` | The current delivery migration creates the `status/availableAt/createdAt` and `status/claimedAt` indexes. |
| Repair migration | `backend/api/prisma/migrations/20260821000000_repair_baseline_indexes/migration.sql:4-16` | The repair migration created the five baseline indexes omitted by the machine-local duplicate migration, including the legacy `status/createdAt` index. |
| Worker query | `backend/api/src/infrastructure/outbox/outbox.service.ts:82-92` | The claim query filters `status` and `availableAt`, then orders by `createdAt`; the current composite index is aligned with that query. |
| Repository references | Full-text search for `OutboxMessage_status_createdAt_idx` | No source or migration references remain outside the repair migration. |
| Live database | Windows `pg_indexes` output | The old index exists in addition to the current ten-index schema. |

## Interpretation

The reported index is a legacy index created by the forward-only repair migration to restore the canonical baseline's five missing indexes. It is not declared by the current Prisma model and does not match the current outbox claim predicate as closely as `OutboxMessage_status_availableAt_createdAt_idx`. The evidence supports a reviewed forward-only cleanup migration, but the cleanup must not be executed against the user's database until the migration is committed and the user explicitly authorizes deployment.

The cleanup decision is separate from the unknown migration-history issue. The database still contains the successfully applied machine-local migration `20260820144702_init`, whose checksum is not present in the repository. Removing the redundant index would make the live schema match the current Prisma datamodel, but it would not make the migration history reproducible. The migration checker must continue to report the unknown migration until that history is explicitly resolved.

## Safety boundary

No `DROP INDEX` statement has been executed. The generated statement is evidence only. No migration metadata was edited, no table was dropped, and no volume or unrelated Docker container was touched.
